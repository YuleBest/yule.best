## 一、什么是 Shell 和 Shell 脚本

首先我们需要知道，“Shell” 和 “Shell 脚本”是两个不同的概念。

Shell 是一个介于系统与用户（你）之间的一座桥梁，让你可以使用它对系统进行操作。那么是不是只有安卓系统才有 Shell 的概念呢？其实不然，包括 Windows、iOS、鸿蒙 OS 在内的绝大部分操作系统都有 Shell 的存在，这也就是我们要学习 Shell 的原因。

Shell 脚本，顾名思义，就是一种给 Shell 编写的脚本。假如说 Shell 是你和系统之间的桥梁，从前你要往桥对面送东西，只能一样一样送，很麻烦；

而学会了 Shell 脚本后，你可以一次性将你要的所有东西都送过去，大大提升了你的效率，这就是“脚本”存在的意义。

---

## 二、Shell 的类型

Shell 的种类很多，但我们经常见到的只有几种：

- **`bash`**：即 Bourne Again Shell，这是大多数 Linux 系统的默认 Shell，Termux 使用的也是 `Bash`，这是本教程重点关注的 Shell
- **`sh`**：即 Bourne Shell，这是始祖级别的 `Shell`，虽然几乎没人用它写代码了
- **`zsh`**：这是 MacOS 的默认 `Shell`，属于 `Bash` 的超集，只要你会 `Bash` 就可以无缝迁移到 `zsh`

这里有一个误区，很多人认为安卓系统的默认 Shell 是 `sh`，但其实是 `mksh` 的精简版本。

## 三、Shell 的运行环境

Shell 和 JS、Python 等是一样的，只要你有一个可以编辑代码的编辑器（比如 MT 管理器、VSCode），和一个解释器就 OK 了。

如果你使用安卓手机观看本教程，推荐你使用 MT 管理器，并且安装扩展包，这样你就获得了一个基础的 Bash 环境了，可以满足教程的需求。

如果你想更进一步，你可以安装 Termux，这样你可以获得带包管理的 `Bash` 环境，可以自由安装各种工具，比如用来处理 json 的 [jq](https://github.com/jqlang/jq)、用来管理代码的 [git](https://github.com/git/git) 等等。

如果你使用 Windows 观看本教程，建议你[安装 Git Bash](https://git-scm.com/install/)，这可以为你提供一个简单的 `Bash` 环境，也能满足本教程的需求。

## 四、第一个脚本

打开文本编辑器，新建一个文件 `1.sh`（sh 代表 shell），扩展名并不影响脚本执行，知道什么意思就好。

输入下面的代码并保存：

```bash
#!/bin/bash

echo "hello, shell"
```

执行它!你会看到 `hello, shell!` 被打印到终端上。

每一个 Shell 脚本的第一行都建议加入 Shebang 行，即以 `#!` 开头，后接 Shell 路径的行，一般情况下，我们写 `#!/bin/bash` 就好。

从第二行开始，我们就可以编写自己的脚本程序了。这里的 `echo` 工具就是用来打印字符串的。

## 五、Shell 命令的基本结构

Shell 命令是由一个命令名 + 参数组成的，参数的数量可以是 0 个及以上。参数之间使用空格分隔。比如上文中的 `echo "hello, shell"`，这里的 `echo` 就是命令名，`"hello, shell"` 就是参数。

这里的英文双引号 `""` 的作用是，告诉 Shell，这是一个参数，而不是两个参数。如果你没有输入引号，Shell 依然认为这是一条命令，但参数变成了两个：`hello` 和 `shell`，这是不符合我们预期的，所以，掌握好用引号的时机很重要。

选项是一种特殊的参数。如果你运行了上面的代码，你可能会发现，输出的结尾带了一个换行，如果你不想要这个换行该怎么办呢？答案就是给 `echo` 加上一个 `-n` 的“选项”。比如 `echo -n "hello, world"`，这样子，`echo` 就不会给输出末尾带上换行了。

简单来说，“选项”可以指定命令该怎么做，“参数”可以指定命令该做什么。选项可以有多个，但是不能是不存在的选项。

对于 `echo` 而言，它的职责就是打印东西，所以它的使用方法很简单：`echo 选项 参数`。`echo` 和绝大多数命令一样，参数的数量可以为 0，这意味着如果你只输入一个 `echo`，那么它将打印一个换行，但不会出现错误。
